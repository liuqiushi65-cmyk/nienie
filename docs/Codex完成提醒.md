# Codex 完成提醒

本机所有任务收到 `agent-turn-complete` 时，当前捏捏恢复完整，轻微上下浮动，轮廓外缘泛起莹绿色柔光，荔枝本体保留原来的鲜红颜色，顶部显示任务名和“本轮已回复”。“已回复”不等于任务或测试成功。

- 动效和气泡持续 12 秒；点击捏捏或关闭气泡提前结束。开始时仅播放一次约 0.32 秒的轻柔上扬 biu，服从现有音量和静音设置；音频恢复被系统延迟超过 0.7 秒时放弃提示，不事后补响。原碎裂 ASMR 不变。
- 正在按住捏捏时先排队，松手后提醒；多个任务依次显示。
- 点击提醒正文进入对应 Codex 对话，右上角 × 只关闭提醒。正文支持键盘 Enter/空格；系统接收跳转后关闭当前气泡，不隐藏捏捏。跳转失败保留提醒可重试。
- 收起的桌宠会随新完成提醒显示。手动再次收起会清除当前提醒队列。
- 同一个任务、同一轮只提醒一次。启动前的历史和超过两分钟的事件不补播。
- 任务名来自本机 `session_index.jsonl` 标题索引；找不到时显示项目名和任务标识前八位。不会读取会话正文，亦不保存完成通知中的输入或回答。

## 安装和还原

跳转使用当前气泡的任务 UUID，经前端和原生端检查后由 macOS 打开 `codex://threads/<任务ID>`。不按标题搜索、不读取对话正文，不执行外部命令。2026-09-23 已只读核对本机 `/Applications/ChatGPT.app` 注册的 codex 协议与客户端资源中的任务链接格式。

```sh
# 先预览已有入口及拟配置入口
python3 scripts/configure_notify.py
# 接入所有本机任务的完成通知
python3 scripts/configure_notify.py --install
# 移除捏捏转发，精确还原原通知项
python3 scripts/configure_notify.py --remove
```

当前 Codex 原有 `notify` 调用 Computer Use 的 `turn-ended`。安装器只改顶层 `notify`，将它接到捏捏接收器；接收器记录提醒元数据后，通过 `exec` 将未经改动的 JSON 参数、环境、标准输入输出和退出码交回原通知程序。其余 Codex 配置和 Hook 信任不变。现有通知项不是可完整解释的单行数组时，安装器停止，不猜测改写整个 TOML。

原入口恢复信息在 `.runtime/notify-forward.json`，不要单独删除此文件；移动或删除本项目之前先运行还原命令。运行时提醒记录在 `.runtime/completions.json`，桌面原生窗口每秒读取一次；无本地端口、云端服务或模型调用。应用需在运行；本轮没有增加开机启动。

## 验证边界

- 单元测试验证完成事件过滤、去重、排队、过期、重启不重播、保留原通知以及配置的安装/还原。
- 浏览器及原生窗口通过明确标记为“联动验收（模拟事件）”的事件验证画面与输入路径。模拟记录不算真实 Codex 接通证据。
- 修改配置不会替已经在运行的轮次强制重新加载。以 `.runtime/completions.json` 出现非模拟的任务/轮次为真实联动依据；如果下一轮没有事件，再检查当前客户端是否已加载更新后的配置。

## 已打开任务不触发时

2026-09-22，用户在接入之前就已打开的任务发送“只回复：测试完成”。任务日志记录该轮正常完成，但接收器没有对应任务/轮次；当时存在的两条其他完成记录不能证明这条任务接通。

先等待其他任务结束，正常退出并重新打开承载 Codex 的 ChatGPT 桌面应用，以重新加载配置，再回到原任务测试。保持捏捏运行，捏碎一些、松手，发送“只回复：测试完成”。只有对应轮次记录出现且窗口实际复原并显示标题，才算这条路径通过。旧任务未重载配置是当前待验证原因，重启是否解决仍需复测；不要以反复发送模拟事件替代这一验证。

后续复测已经收到当前任务的真实完成事件，用户截图确认完整荔枝与任务气泡，并明确确认轻浮正常。上述失败记录作为排查历史保留。

官方接口：[OpenAI Docs — Notifications](https://learn.chatgpt.com/docs/config-file/config-advanced#notifications)。原有 Hooks 的工作中、等待操作状态仍可选用，但不是完成提醒的前提；`Stop` 不用于新的复原效果。
