# 桌面捏捏：设计与实施草案 v0.1

日期：2026-09-20。状态：用户于 2026-09-21 授权开始最小方案实施。桌面形态、双风格与首批三个物体进入实施；手感仍待体验验收。

## 1. 目标与已确认决定

让用户在 Codex 思考、执行和输出期间，随手通过声音与形变消磨等待时间，随时回到工作。

用户已确认：透明悬浮小物体，像桌宠；仿真食物与可爱玩具两种风格都可以有。用户要求物体丰富，包含水果、食物，鼠标点按有声音和捏碎效果。

## 2. 候选体验

桌面角落放一个约 180–260 px 的物体，默认无大面板；悬停显示很小的换物、重置、音量与移动把手。尺寸为待体验调整的建议。

- 悬停：物体轻微响应，展示可捏区域；默认不发声。
- 点按：点击处凹陷并产生一小片裂纹，立即配合短促脆响。
- 按住：按时长模拟加力，先变形、再连续开裂，最后露出软芯。普通鼠标没有真实压力输入。
- 松开：软芯部分回弹，已破的壳保留，后续点按继续破坏尚完整的区域。
- 捏完：短暂保留成果，出现“再来一个”；可选自动换新，捏碎和 Codex 完成不互相绑定。
- 移动：拖专用把手，避免拖动窗口与揉捏冲突。
- 透明区域：可点击穿透，不遮挡底层应用；物体区域接收交互。是否支持跨桌面、全屏及多显示器须原型实测。

## 3. 物体与声音设计

| 材质 | 首批候选 | 形变 | 声音方向 |
|---|---|---|---|
| 薄蜡壳、软芯 | 草莓、橘子、桃子 | 局部凹陷、放射裂纹、薄壳掉落、果肉挤出 | 密集细碎咔嚓 |
| 厚脆壳、软芯 | 巧克力、脆皮雪糕 | 大块断裂、内部缓慢变形 | 较低沉的断裂叠细碎声 |
| 酥松碎屑 | 曲奇、马卡龙、可颂 | 掰断、压扁、掉渣 | 干燥酥碎声 |
| 弹性软胶 | 软糖小熊、猫爪、麻薯 | 压扁、侧向鼓起、回弹 | 柔软挤压与轻噗声 |

先做草莓、曲奇、猫爪三个手感样本；手感认可后再扩到约 12 款。丰富度同时包含造型与材质，不把换颜色当新手感。

音频由接触、主裂纹、碎屑三个层次构成，由同一个破裂事件驱动画面与声音。每种材质使用多个短采样避免机械重复；完整破壳后不再播放完整壳的第一次爆裂声。素材采用原创或有授权的采样，研究视频仅作为参考。运行时本地播放，不调用模型生成音效。

## 4. Codex 联动与证据边界

候选状态：工作中、需要操作、完成、异常、未连接。思考与响应阶段都能捏，第一版无需区分模型内部推理阶段。

- 工作中：显示低存在感状态点，允许持续捏。
- 需要操作：显示提示，用户自己回到 Codex 处理。
- 完成：柔和亮一下，不立即销毁正在捏的物体，不抢焦点。
- 未连接：明确显示未知，允许继续自由捏；不根据时间猜测已完成。
- 多任务：第一版绑定一个选定任务，避免其他任务完成造成误报。

官方 Hooks 文档列有 UserPromptSubmit、Stop、Interrupt、PermissionRequest 等生命周期事件，可作为候选入口。其在当前桌面客户端的可用性、停止与异常语义、可信配置流程尚未实测。桥接只读取最少事件字段，不传输提示词正文，不向 Codex 下发操作。

App Server 文档提供 turn/started、turn/completed 等事件，但自行连接或启动一个服务，不等于能够监听已有桌面任务。若必须更换用户的任务入口，这一代价需要重新对齐，不能悄悄改成另一个 Codex 客户端。

官方也有 Pets 自定义外观和活动展示说明；所查页面没有证明自定义宠物可运行任意捏碎逻辑与 ASMR 音频。因此“换宠物皮肤”只作低成本外观替代候选。

## 5. 最简单够用的实现候选

单用户、单机 macOS，一个悬浮物体，无账号、云服务、数据库。候选为薄桌面窗口层加本地渲染及音频；具体框架待透明窗口、点击穿透和焦点验证后决定。

优先尝试受控的 2.5D 网格变形、分区裂纹和少量碎片。优势是能控制点击位置与声画同步；代价是视角和破坏方式有限。完整 3D 软体及断裂模拟只在用户确需自由旋转、任意方向挤压且原型达不到效果时考虑。

关键风险：即使窗口和状态接入成功，平面拉伸加爆炸粒子仍可能完全没有捏捏感。手感由 Lexie 戴耳机体验验收，程序测试不能替代。

## 6. 实施顺序与门禁

1. 方向确认后，制作一个草莓的可交互样本，验证受力位置、累积破壳与音频；状态模拟必须标注。
2. 验证真正的 macOS 透明悬浮、点击穿透、不抢键盘焦点，以及本机 Codex 事件入口。
3. 补齐曲奇与猫爪，形成三种材质闭环，真实任务开始、等待、完成联动通过后才称联动 MVP。
4. 获得手感认可后扩充物体库；每个独立能力小步提交，状态机先测再改。

拟定指标：有线或内置输出下输入到视听反馈 P95 < 50 ms；连续交互目标 60 fps；静置不持续全速渲染。均是验收目标，尚无测量结果；蓝牙延迟单独记录。

免费本地研究与代码阶段外部生成调用预算为 0。任何素材购买、付费生成或素材上传另行确认具体范围。测试原有任务状态可以观察，不额外触发付费模型任务。

未决项：首个物体外观、手感认可、窗口技术、状态入口。Lexie 决定体验方向，Codex 提供验证证据；在各对应实现阶段前决定。暂无发布日期承诺。

已实现三种物体、本地合成音效、AppKit/WebKit 透明悬浮窗口和项目级 Hooks 接收器。原生窗口层因本机 Swift/SDK 不匹配改用 Objective-C，不改变产品形态。项目 Hooks 已安装；真实信任与生命周期验证尚待完成，不能称真实联动验收通过。详细证据见 ../验证记录.md。

## 9. 实施决策记录

- 用户明确要求开始最小方案实施，范围为三种手感样本与桌面/Codex 联动。
- 使用零第三方依赖的 AppKit + WebKit，不引入服务器。
- 首版音频采用原创程序合成，真实录音品质属于后续手感调校范围。
- 本机未发现可直接连接的共享 App Server 控制 socket，采用项目 Hooks，不另起模型会话。
