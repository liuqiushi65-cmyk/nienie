# 首次公开发布

代码、文档与项目生成的图片和动画采用 MIT；第三方软泥实录保留 CC0。具体文件范围见根目录 `THIRD_PARTY_NOTICES.md`。发布分为源码 ZIP 与运行素材 ZIP，运行素材保留在 Git 之外。

## 1. 制作运行素材包

在维护者具有完整素材的项目根目录执行：

```sh
python3 scripts/runtime_assets.py pack build/nienie-runtime-assets-v1.zip
python3 scripts/runtime_assets.py verify build/nienie-runtime-assets-v1.zip
```

包只包含当前代码需要的八套图集、八张软芯、CC0 软泥样本、许可说明与 SHA-256 清单，不扫描打包整个 `artifacts/`。原始录屏、账号信息、任务通知、配乐、试验视频与旧人声均不属于该清单。已有同名包不会被覆盖，重打包请使用新文件名。

维护者于 2026-09-27 已确认生成图片和动画按 MIT 开放，素材 ZIP 内附 LICENSE 与范围说明。原始参考录屏、外部配音和配乐不属于这项授权，也不在发布包内。

## 2. 导出没有旧开发历史的源码

先提交本轮修改，确认工作区干净，再执行：

```sh
git archive --format=zip --prefix=nienie/ --output=build/nienie-source-v0.1.0.zip HEAD
shasum -a 256 build/nienie-source-v0.1.0.zip build/nienie-runtime-assets-v1.zip > build/SHA256SUMS.txt
```

`git archive` 仅导出该次提交的跟踪文件，不带 `.git`、运行状态、忽略目录和旧提交。当前源码已使用原创电子短哼，但本机旧历史包含未确认可再分发的第三方人声 PCM，因此首次公开从该快照创建新仓库。不要将本机开发仓库直接设置远程后全量推送，也不要将现有旧应用包误作新的发行包。

本机开发记录保持不变，不通过本脚本删除或重写。源码包与素材包共同支持用户在自己的项目路径构建；当前应用内有构建时路径，未把维护者机器上构建的 `.app` 当作通用安装包发布。

## 3. 在干净目录验证

```sh
unzip nienie-source-v0.1.0.zip
cd nienie
python3 scripts/runtime_assets.py install ../nienie-runtime-assets-v1.zip
npm test
bash scripts/test-native.sh
bash scripts/build.sh
```

构建所需 Python 部分仅使用标准库。若运行完整抠图测试，再创建虚拟环境、安装 README 中的处理依赖；素材包不带源视频，因此真实源片测试可能跳过，需要如实记录。

生成源码包后，可在解压出的 `nienie/` 目录执行 `git init -b main`，确认 `.runtime/`、`artifacts/`、`build/` 被忽略后提交初始版本，再关联自己的 GitHub 仓库。素材 ZIP 和 SHA256SUMS 作为 Release 附件上传；源码仓库应保留 README、LICENSE 和素材声明。

本指南只描述发布流程，不会自动创建远程仓库、上传文件或改动原有 Codex 配置。
